# 旁白与字幕写作指南

## 结构

```json
{
  "<sceneId>": {
    "text": "整段旁白，交给 macOS say（Tingting）合成",
    "captions": ["字幕第一条", "字幕第二条", "字幕第三条"]
  }
}
```

key 与 `scenes.tsx` 的 `SceneEntry.id` 一一对应，顺序一致。

## 时长

- 语速约 5 字/秒（`SPEAK_RATE = 192`）。场景帧数 = 12 帧开头留白 + 配音时长 + 22 帧结尾留白。
- 单场景 40～110 字，约 8～20 秒。标题页和回顾页可以短一些（30～60 字）。
- 全片建议 3～5 分钟，即 900～1500 字。超出就合并或删减场景，不要把每个场景都写长。

## 写给耳朵听

- 一句话只讲一个意思，多用逗号断句，句子不超过 30 字。
- 括号、斜杠、箭头、`/`、`→` 这类符号读不出来或会读错，改写成完整句子。
- 英文缩写尽量换成中文说法（RAG → 检索增强；TTL → 存活时间）。必须保留的英文（Agent、token、git、MemGPT）可以直接写，Tingting 能读。
- 数字写成读法：「80% 到 90%」写成「八到九成」更自然；「N 轮」写成「最近几轮」。
- 画面已经写了的细节，旁白不必逐字重复；旁白讲「为什么」和「结论」，画面列「要点」。

## 字幕

- 每场景 2～3 条，每条 ≤ 20 字（字幕 40px，单行显示）。
- 按旁白的先后顺序概括，不要求逐字一致。字幕按字数加权分配时间，所以每条长度别相差太大。
- 字幕可以用 `·`、`→`、`+` 之类的符号压缩信息，这一点和旁白相反。

## 与画面的配合

- 场景开头 12 帧才开口，避开过场淡入，画面元素一般在 12～60 帧依次浮现，和开口同步。
- 结论横幅、强调标签出现的帧，最好落在旁白讲到结论的时候；需要提示音时在那一帧加 `ding`。
